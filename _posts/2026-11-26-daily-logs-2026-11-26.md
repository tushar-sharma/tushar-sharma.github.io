## 1Password

My notes on [Beyond Branch Protection: Understanding GitHub Attack Paths](https://specterops.io/blog/2026/11/25/beyond-branch-protection-understanding-github-attack-paths/).

**What happened at 1Password?**

Someone got into an employee's corporate GitHub account and gained access to some backend systems. 1Password says the attacker copied some customer account information, including names and email addresses. Customer vaults were unaffected. [1Password's update](https://1password.com/blog/update-on-nov-2026-security-incident)

**Understanding some concepts**

1. **Identity**. An identity represents a user or a workload in a system. We can assign permissions to that identity.

2. **Identity provider (IdP)**. A trusted service that authenticates identities and provides information about them.

3. **Active Directory (AD)**. Companies often store user identities in Active Directory, which runs on Windows servers called domain controllers.

4. **How does an IdP talk to AD?** An application can use LDAP to look up directory entries or Kerberos for authentication. With delegated authentication, Okta sends the user's credentials through its AD agent, and an AD domain controller validates them. The agent initiates the connection to Okta.

   If the application uses OpenID Connect (OIDC), Okta can issue an ID token as proof of authentication. Okta signs it with its private key. The application checks the signature with Okta's public key and validates the token's claims.

5. **GitHub identity**. GitHub keeps track of user identities. For GitHub Actions, we have *workload identity*, which represents a workflow job.

   GitHub Actions has an OIDC provider that Microsoft Entra ID can trust. A workflow job gets an OIDC token from GitHub and exchanges it for an Entra ID access token. What the job can do in Azure depends on the permissions assigned to the Entra identity it signs in as.

   To tell Entra ID which GitHub identities to trust, we can set up a federated identity credential (FIC). Entra ID checks the token's issuer, audience, and subject against that credential. The subject can identify a specific repository and branch, tag, or environment.
